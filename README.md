# Бот для поиска команды

Рабочая реализация прототипа для одного соревнования: обычные сообщения и кнопки Telegram, русский интерфейс, Python 3.12, aiogram 3.31.0 и SQLite. Одна серверная программа, без веб-приложения и отдельного сервера базы.

**Статус проверки:** общая заявка в команду без позиции, заявка на позицию и обратный сценарий приглашения пройдены локально через настоящий Dispatcher aiogram с двумя независимыми пользовательскими ID. Подменён только транспорт Telegram. Автоматическая проверка в настоящем Telegram с двумя аккаунтами не выполнена. Пользователь запускает бота и проверяет его вручную; эти действия не заменяют автоматический отчёт.

## Локальный запуск в Windows / PowerShell

Откройте терминал в папке проекта. Требуется Python 3.12 и доступ к PyPI и Telegram.

```powershell
Set-Location C:\Users\bekza\Desktop\se
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item -LiteralPath config.example.json -Destination config.json
```

В текущей рабочей папке виртуальное окружение уже создано и зависимости установлены. Активация окружения и изменение ExecutionPolicy не нужны. `requirements.lock.txt` фиксирует все версии, с которыми выполнены проверки; `requirements.txt` содержит три прямые зависимости.

Получите токен: откройте [официального @BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте название и уникальное имя бота по его подсказкам. Он выдаст токен. Процесс описан в [официальной инструкции Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).

Введите токен скрыто, чтобы не оставлять его в истории команд:

```powershell
$botSecret = Read-Host 'Токен от BotFather' -AsSecureString
$env:BOT_TOKEN = [System.Net.NetworkCredential]::new('', $botSecret).Password
.\.venv\Scripts\python.exe -m app.main
```

После запуска откройте своего бота в Telegram и нажмите «Начать» или отправьте `/start`. Каждый участник должен сам начать личный диалог с ботом. Бот работает только в личных чатах.

Остановка — `Ctrl+C`. После остановки можно очистить переменную текущего терминала:

```powershell
Remove-Item Env:BOT_TOKEN
Remove-Variable botSecret
```

Не запускайте две копии бота с одним токеном. Long polling работает без домена, webhook и открытого входящего порта. При запуске бот отключает существующий webhook этого токена, сохраняя очередь обновлений. [.env.example](.env.example) — пример переменной, файл `.env` автоматически не загружается. Токен не нужно отправлять в чат или записывать в исходники.

## Конфигурация без секретов

```json
{
  "name": "Учебный хакатон",
  "max_team_size": 4,
  "timezone": "Asia/Almaty",
  "database": "data/bot.db",
  "max_offers_per_day": 10
}
```

Выбор способа участия, интенсивность, цель, выбор времени и интересующие темы удалены из интерфейса и правил подбора. В карточке команды используется подпись «Тема». Если тему пропустить, показывается «Тему выберем вместе». Старые анкеты и команды продолжают работать; прежние поля не влияют на поиск. Параметр `timezone` оставлен для совместимости конфигурации и больше не отображается в боте.

`max_team_size` включает капитана, допустимые значения — 2–20. Фактический состав не может превышать лимит. Открытые позиции не резервируют вместимость для общих заявок; когда команда заполняется, оставшиеся позиции закрываются. Настройки соревнования задавайте перед началом использования; смена соревнования и уменьшение лимита существующих команд не поддерживаются. Для другого соревнования укажите новую базу.

Без `config.json` используется `config.example.json`. Другой путь можно указать переменной `BOT_CONFIG`. Относительный путь базы отсчитывается от рабочей папки запуска. Данные базы, `config.json`, `.env` и виртуальное окружение исключены из Git.

## Что реализовано

- Анкета: ядро из четырёх шагов — роль, навыки, описание опыта и уровень опыта. После предпросмотра можно сохранить и перейти к поиску либо дополнить анкету. Имя из Telegram подставляется в черновик; в дополнениях можно изменить имя, выбрать дополнительные роли, добавить проекты и ссылки. Сохранённые анкеты и черновики прежней формы поддерживаются.
- Черновики анкеты, команды, места и фильтры сохраняются в SQLite. После перезапуска `/start` предлагает продолжить черновик; `/cancel` отменяет его. Записи FSM старше семи дней очищаются при запуске.
- Главное меню зависит от анкеты, членства и прав капитана. После изменений и доставки уведомлений клавиатура обновляется.
- Роли выбираются кнопками. Навыки — из справочника с добавлением своих.
- Создание команды автоматически создаёт членство капитана. Команда содержит название, тему, состав и статус набора. Тему рекомендуем указать; пропуск требует одного подтверждения и не блокирует создание.
- Каждое место рассчитано на одного человека: роль, задачи, обязательные и желательные навыки, готовность принять новичка.
- Раздел «Команды»: все нерасформированные команды, состав, статус возможности подать заявку. Видны также заполненные команды и команды с приостановленным набором. Просмотр доступен без анкеты и участникам других команд.
- Общая заявка в команду без выбора позиции. Для заявки нужна анкета, свободное членство, открытый набор и свободное место в лимите команды.
- Поиск свободных участников для конкретной позиции, фильтры по роли и навыкам; пять карточек на странице, подробности, навигация и пустая выдача.
- Рекомендации с понятными объяснениями, без AI, процентов совместимости и общего рейтинга.
- Общие заявки в команду, заявки и приглашения на конкретное место с сообщением; принятие, отклонение, отмена отправителем и история.
- Изменение команды и места, приостановка набора, роли в составе, выход, передача капитанства и расформирование. Капитан может исключить другого участника после подтверждения; старая кнопка не исключает его после повторного вступления.
- Закрытое или заполненное место можно открыть снова либо создать его копию. Нужны капитанские права, открытый набор и свободная вместимость с учётом уже открытых мест. Старые предложения не восстанавливаются.
- Проверки прав при каждом действии, защита от дубликатов и старых кнопок, атомарное вступление.
- Сохранённая очередь уведомлений с повторными попытками и блокировкой попытки на 60 секунд. После аварии с неизвестным результатом повтор получает нейтральную пометку. Ошибка отправки не отменяет вступление.
- Причина неактуальности показывается в истории и уведомлении. После закрытия места или приостановки набора есть подсказка о новой заявке после возобновления.
- Не более 10 новых предложений за последние 24 часа по умолчанию и не чаще одного в три секунды на отправителя; учитываются заявки и приглашения во всех статусах. `max_offers_per_day` допускает целые значения от 1 до 100. Ошибочные попытки квоту не расходуют; отмена предложения её не возвращает.
- «Мои данные»: скрытие анкеты и удаление с двумя подтверждениями. Удаляются анкета, членство, предложения, связанные уведомления, собственные черновики и техническая запись пользователя. Капитан сначала передаёт управление или расформировывает команду. После удаления можно зарегистрироваться заново.
- Добровольная передача введённого контакта только после предпросмотра и подтверждения получателей. Контакты отсутствуют в публичных карточках.

## Правила состояния

Один человек состоит максимум в одной команде. До вступления можно иметь несколько предложений. На пару «участник — место» допускается только одно ожидающее предложение любого типа. Для общей заявки допускается только одна ожидающая заявка на пару «участник — команда». После отклонения или отмены можно отправить новую.

Предложение проходит из «Ожидает решения» в один конечный статус: «Принято», «Отклонено», «Отменено», «Неактуально». Заявку решает текущий капитан, приглашение — приглашённый человек. Завершённое предложение повторно не активируется. Повторное нажатие сообщает сохранённый результат.

Принятие выполняется в `BEGIN IMMEDIATE`: проверка прав, текущего членства, вместимости и статуса набора; для заявки на позицию — также состояния места и требований. Общая заявка не зависит от требований позиций. Роль при общем вступлении берётся из анкеты и может быть изменена капитаном в составе. В той же транзакции создаётся членство, принимается предложение, завершаются конфликтующие предложения и записываются уведомления. Для позиционной заявки место заполняется. Если команда достигла лимита, оставшиеся позиции закрываются и ожидающие заявки в неё становятся неактуальными. Затем выполняется commit, после которого начинается доставка.

При вступлении завершаются все другие активные предложения человека и предложения на занятое место. При создании собственной команды предложения её создателя также становятся неактуальными. При закрытии места, приостановке набора или расформировании завершаются связанные предложения. Возобновление набора старые предложения не восстанавливает.

Редактирование описания или требований места требует новых предложений. При изменении анкеты завершаются только предложения, обязательные требования которых больше не выполняются. Окончательная проверка требований всё равно выполняется внутри принятия.

Скрытие анкеты убирает человека из поиска участников и отключает автоматические рекомендации для него. Самостоятельный поиск и уже отправленные предложения сохраняются. Человек в команде также исключается из поиска свободных людей. Его данные состава остаются в карточке команды.

Капитан меняет роль в составе и может исключить другого участника, но не себя. Личную анкету редактирует сам участник. После выхода или исключения место не открывается автоматически: капитан решает открыть его снова, скопировать или создать новое. Перед собственным выходом и удалением данных капитан передаёт управление действующему участнику или расформировывает команду. Добавление человека без его согласия запрещено.

## Прозрачный подбор

Сначала исключаем несвободных и скрытых участников, закрытые места и команды, отсутствие любого обязательного навыка и отсутствие заявленного опыта там, где новичков не принимают.

Время участия не собирается и не используется как ограничение поиска. Его участники согласовывают между собой.

Сортировка по очереди:

1. Основная роль совпадает; затем дополнительная; затем остальные.
2. Число совпавших желательных навыков по убыванию.
3. Стабильный порядок по ID.

Совпадение роли влияет на порядок, обязательные навыки — на допуск. Для участника команда показывается один раз по её лучшему подходящему месту; остальные открытые места доступны в карточке команды. Для капитана подбор выполняется только внутри конкретного места.

Раздел «Команды» показывает составы независимо от соответствия требованиям отдельных позиций. Карточка сообщает, можно ли подать общую заявку: «Можно отправить заявку», «Заявка уже отправлена», «Команда заполнена», «Набор приостановлен», «Сначала заполните анкету» или «Вы уже состоите в команде». Выбранные роли и навыки фильтра проверяются по составу и открытым позициям. Для свободного участника рекомендации сначала показывают команды с подходящей позицией, затем команды, в которые можно подать общую заявку. На неподходящую конкретную позицию заявку отправить нельзя, но в команду в целом — можно.

Нормализация навыков: Unicode NFKC, регистр, пробелы, `ё/е`, известные синонимы (`js/javascript`, `postgres/postgresql` и другие). `C`, `C++` и `C#` различаются. Пользовательские навыки нормализуются так же; произвольные неизвестные синонимы не угадываются.

## Приватность

База содержит Telegram ID, ID личного чата, анкету, членство, предложения и уведомления. Имя Telegram подставляется в черновик и показывается перед сохранением; его можно изменить. Username, телефон, дату рождения, адрес, документы и PDF бот автоматически не собирает. Анкета может содержать добровольно добавленные ссылки; они видны при подробном просмотре. Навыки и опыт указаны самими пользователями, бот их не проверяет.

В карточках команды контакты отсутствуют. «Поделиться контактом» предлагает самому ввести контакт, показывает получателей и требует отдельного подтверждения. Изменение состава до отправки отменяет отправку и требует нового подтверждения. Проверка получателей выполняется в той же транзакции, что и сохранение уведомлений. Отправленные сообщения отозвать нельзя.

В журналы приложения попадают только фиксированные технические коды ошибок. Сырые Telegram Update, тексты сообщений, содержимое анкет и исключения транспортных библиотек не записываются. Сама SQLite-база содержит пользовательские данные в открытом виде; хранить её следует на доверенном компьютере.

## Проверки и демонстрация без токена

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m scripts.demo
```

Демонстрация запускает реальные обработчики и временные SQLite-базы с пользователями 101 и 202. Проверяются три сценария: общая заявка без позиции, заявка на позицию и приглашение. Только сетевой транспорт Telegram подменён. Она не отправляет сообщения настоящим людям и не использует `data/bot.db`. Все имена помечены `[ТЕСТ]`. Созданный протокол: [docs/demo-transcript.txt](docs/demo-transcript.txt).

Обновления схемы выполняются автоматически при запуске. Перед каждым новым изменением существующей базы рядом создаётся копия SQLite с суффиксом `.before-*.bak` (например, `data/bot.db.before-fsm.bak`). Повторный запуск не пересоздаёт таблицы и не заменяет эти копии. ID, история предложений, анкеты и состав сохраняются. Новая пустая база создаётся сразу по текущей схеме. Не удаляйте базу для обновления.

Удаление через «Мои данные» действует на рабочую базу. Старые резервные копии и уже отправленные сообщения могут содержать прежние данные; очистку копий выполняет владелец запуска. В расформированных командах ID удалившегося бывшего капитана заменяется технической записью без персональных данных. Черновики других людей, содержащие ссылку на удалённого участника, отменяются. Уже начатую сетевую отправку отозвать невозможно.

Быстрая проверка нового сценария: капитан создаёт команду без позиций; второй аккаунт открывает «Команды» → «Команда и состав» → «Подать заявку в команду» → пишет сообщение → «Отправить»; капитан открывает заявку и принимает. Состав увеличивается на одного человека.

Проверяются обе последовательности: анкета → команда → место → самостоятельный поиск и рекомендации → заявка → принятие → обновлённый состав; затем приглашение → согласие участника → контакт по подтверждению → выход. Результаты и границы проверки: [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Короткая демонстрация в настоящем Telegram

Используйте два разных аккаунта: А — капитан, Б — участник. Оба открывают бота и заполняют анкеты. Для простоты укажите Python и PostgreSQL.

1. А создаёт команду с темой и место бэкенд-разработчика: Python обязателен, PostgreSQL желателен, новичков принимаем.
2. Б открывает «Найти команду», смотрит состав и требования. Затем открывает «Подходящие команды» и читает объяснение.
3. Б отправляет заявку с сообщением. А открывает «Заявки и приглашения» и принимает её.
4. У обоих состав содержит двух человек, место заполнено. А создаёт второе место и убеждается, что Б отсутствует в поиске свободных участников. Повторная старая кнопка принятия не добавляет человека ещё раз.
5. Б выходит: первое место остаётся заполненным. А на втором месте находит Б и приглашает. Б смотрит команду и принимает приглашение.
6. Б добровольно делится контактом через предпросмотр. А получает его. До подтверждения контакт не отправляется.

Дополнительная ручная проверка новых функций:

1. Б начинает анкету, останавливается на навыках. Перезапустите программу с той же базой; `/start` → «Продолжить заполнение» должно вернуть навыки. Повторите с созданием команды/места и фильтрами.
2. Пройдите анкету обеими ветками: сохранение после четырёх шагов и дополнение с псевдонимом. Проверьте меню до анкеты, без команды, в составе и у капитана.
3. А исключает Б через подтверждение. Нажмите старую кнопку ещё раз; повторного действия быть не должно. Б снова может подавать заявки.
4. А открывает заполненное место снова либо создаёт копию. Проверьте сохранение требований, лимит вместимости и отсутствие восстановленных старых предложений.
5. Б подаёт новую заявку, А приостанавливает набор. Б получает причину и подсказку, после возобновления отправляет новую заявку. Повтор старого принятия не должен вступить в команду.
6. А приглашает Б, Б принимает. Проверьте уведомления и обновлённое меню. После повторного вступления старая кнопка исключения из предыдущего состава не действует.
7. Проверьте две быстрые отправки разных предложений; вторую бот должен отклонить до истечения трёх секунд. После десяти отправок за 24 часа следующий новый запрос отклоняется, включая отменённые предложения.
8. Б открывает «Мои данные», отменяет удаление, затем удаляет с двумя подтверждениями и заполняет анкету заново. А как капитан не может удалить данные, пока не передаст управление или не расформирует команду.
9. При создании команды пропустите тему, вернитесь к вводу, затем подтвердите пропуск. Должен быть один вопрос «Пропустить без темы?».

Для конфликтов используются автоматические тесты с двумя потоками и отдельными подключениями к SQLite. Дополнительные команды и пользователи в этих тестах отделены от реальной базы.

## Ограничения прототипа

- Живая проверка с двумя аккаунтами ещё не выполнена; нет подтверждения реальной доставки и удобства интерфейса на телефоне.
- Один процесс, одно соревнование и небольшое число пользователей. Поиск пока выполняется в памяти по сохранённым записям; это не решение для больших каталогов.
- Черновики и фильтры живут семь дней с последнего обновления записи FSM; очистка выполняется при запуске. `/cancel` отменяет черновик, `/menu` выходит из него. Старые сохранённые черновики продолжаются по прежней последовательности полей.
- Нет сбора времени участия, календаря и проверки реального присутствия. Расписание участники согласовывают самостоятельно.
- Произвольные синонимы навыков, достоверность опыта и качество проектов не проверяются.
- Нет админ-панели и модерации. Лимиты действуют на предложения одного Telegram ID и не защищают от множества аккаунтов или потока произвольных входящих сообщений. Автоматический срок хранения задан только для FSM, остальные данные удаляются по запросу пользователя.
- SQLite-база не зашифрована. Резервное копирование и управление доступом к компьютеру выполняет владелец запуска.
- Уведомления имеют до пяти попыток, в том числе незавершённых из-за аварии; блокировка бота делает доставку невозможной. После неопределённой попытки повтор задерживается минимум на 60 секунд и помечается. Гарантии единственной доставки нет. Результат предложения остаётся доступен в меню.
- Удаление не стирает сообщения из Telegram, резервные копии и содержание общих команд/мест, созданных ранее. Рабочая база и резервные копии не зашифрованы.
- Пересылка контакта действует на подтверждённый текущий состав. Новый участник не получает старые контакты автоматически; уже доставленный контакт отозвать невозможно.
- Нет Mini App, AI, микросервисов, платежей, группового чата, автоматического добавления в Telegram-группу и обработки PDF.

## Где находится логика

`app/bot.py` — меню, диалоги, кнопки и доставка уведомлений; `app/forms.py` — поля форм; `app/cards.py` — русский текст карточек; `app/catalogs.py` — короткие списки и нормализация; `app/storage.py` — постоянный FSM; `app/services/core.py` — правила и операции; `app/db.py` и `app/schema.sql` — подключения, миграции и схема SQLite; `app/main.py` — запуск.

Для небольшого проекта обработчики и сервисы объединены по слоям вместо множества файлов по сущностям. Отдельного веб-сервера и ORM нет. Сетевые операции находятся вне транзакций, короткие операции SQLite выполняются через `asyncio.to_thread`, соединения не разделяются между потоками.

Официальные источники, проверенные при разработке: [aiogram — long polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html), [FSM](https://docs.aiogram.dev/en/latest/dispatcher/finite_state_machine/index.html), [BaseStorage aiogram 3.31.0](https://docs.aiogram.dev/en/v3.31.0/_modules/aiogram/fsm/storage/base.html), [Python 3.12 — sqlite3](https://docs.python.org/3.12/library/sqlite3.html), [SQLite — транзакции](https://www.sqlite.org/lang_transaction.html), [частичные индексы](https://www.sqlite.org/partialindex.html), [Telegram Bot API](https://core.telegram.org/bots/api), [pytest](https://docs.pytest.org/en/stable/).
